# mtgproxy — working notes

## Where files go

**Never create a new directory, or add to `docs/`, for something that belongs to a
single deck.** Everything about one deck lives in `examples/`, named after the
deck, beside its decklist:

```
examples/nazgul.txt            the decklist
examples/nazgul.cards.json     stored card data (generated by `sync`)
```

A deck guide, a token list, print history — if it is about one deck, it is
`examples/<deck>.<something>`, not a folder of its own and not `docs/`.
`docs/` is for the project: `PLAN.md` (architecture) and `ROADMAP.md`
(designed-but-not-built features). Adding a per-deck page there was wrong once;
do not repeat it.

**Watch out:** `examples/` is the decks directory, and `listDecks()` matches
`*.md` as well as `*.txt`. Any markdown file dropped in there is treated as a
decklist and `sync` will adopt it as a deck, copying it to `<name>.txt` and
listing it in `decks.index.json`. So a markdown file in `examples/` must be an
actual decklist, not prose about one.

## Regenerating deck data

`sync` writes `decks.index.json` from **only the decks passed to it**, so
`sync <one-deck>` drops every other deck from the index. Always run it bare:

```bash
node apps/cli/dist/index.js sync
```

## Verifying card facts

Never state a card's oracle text, mana cost, colour identity, legality or Game
Changer status from memory — check Scryfall. Colour identity in particular:
several cards that look perfect for a deck are off-colour (In the Darkness Bind
Them and Saruman, the White Hand are Grixis, not Dimir).

`/cards/collection` finds tokens by name; `/cards/search` hides them unless the
query includes `include:extras`.
